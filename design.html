Design system

Every token and component the site uses, rendered live. This page pulls from style.css rather than describing it, so if something looks wrong here it is wrong everywhere.

How to use this

Change a value in the :root block of style.css and it propagates through every page. Reach for an existing token before inventing a hex code — that is the whole point of them, and it is what keeps seven content pages and three application pages looking like one site.

Two themes, one set of names

Every token below has a value in both the light and the dark theme, and the page you are reading re-renders in whichever is active — use the toggle in the masthead. That is the reason nothing anywhere may hardcode a hex: a literal colour is, by definition, wrong in one of the two. The dark theme follows the operating system until the toggle is used, after which the choice is pinned in localStorage.

Brand

Crimson, from the mark. Used sparingly and on purpose: the badge, the current nav item, the primary action, links, and bearish data. Everything else on the page is ink on white — a page that is almost entirely black-on-white with a little red is what reads as a research house, and the moment red becomes the furniture it reads as a landing page instead.

--brand-solidbuttons, badge · same in both themes
--brand-solid-hoversolid fill hover
--brand-500links, active nav
--brand-800deep crimson
--brand-100tint border
--brand-050tint fill
Why two red tokens

--brand-solid is one crimson used in both themes for anything filled — buttons, the badge, tool flags — because white on it clears AA at 5.97:1 either way. Links need the opposite treatment: --brand-500 lightens in the dark theme so it stays legible on a dark page, and white text on that red would fail. One token could not do both jobs, so there are two.

Market semantics

These four are the only colours that carry meaning, and they are never used for anything else.

--bullbullish, profit
--bearbearish, loss, danger
--warntime, caution
--violetmidpoints, code
Meaning before decoration

Green is bullish and red is bearish everywhere on this site — in prose, in tags, in every SVG. Amber means time or caution. Violet marks midpoints such as consequent encroachment and mean threshold. A reader learns these in the first diagram; breaking them later costs comprehension for the sake of variety.

Red is the exception that proves it. Bearish red and the brand crimson are deliberately the same colour: on a trading site red already means down, and inventing a second red would make two things that mean the same thing look different. What keeps it readable is volume — red covers a few percent of any page here. The original palette used bullish green for links, buttons, the brand, the active nav item and the focus ring as well as for direction, so green appeared several hundred times per page and signalled nothing.

Type

Three families, each with one job. Source Serif 4 carries content — headlines and running prose, because extended reading is what this site is for. Libre Franklin carries the interface: navigation, labels, buttons, table headers, anything that is a control rather than a sentence. It is a Franklin Gothic descendant — the newspaper and banking grotesque — which is why the chrome reads institutional rather than like a product launch. JetBrains Mono is reserved for data — prices, R multiples, codes, source — where a tabular figure actually matters.

The scale is fluid: sizes interpolate between phone and desktop with clamp(), so no breakpoint is needed to keep text readable.

Buttons

Two weights, and that is deliberate. A page with three equally loud actions has no primary action.

Diagram colours

Diagrams are hand-written inline SVG so they inherit the palette and need no assets. A presentation attribute cannot hold a var(), so the colour has to live in a class — which is also what lets one diagram be correct in both themes.

svg-f-* sets fill, svg-s-* sets stroke; the two are separate so an element can carry a wash and an outline independently, and per-element opacity still controls the strength of a zone.

Layout

--wrap1040px · reading pages
--wrap-wide1240px · members, lesson, admin, this page
--measure78ch · prose column, everywhere

The wide pages keep prose at 78 characters but let images, tables and video use the full column. A slide is content; a paragraph is reading. They do not want the same width, which is why the wide layout is a container class rather than a global change.

Empty readout

Every tool starts empty rather than showing zeros. A zero is a claim; an empty state is honest about having nothing to say yet.

Fill in an entry and a stop and this fills in. Until then there is nothing here that would not be invented.

Statistic bars

Used throughout stats.html. Green is a positive expectancy, red negative — the same colour code the diagrams use. Slices under ten trades carry an n= tag and stay visible rather than being hidden, so a thin sample teaches instead of disappearing.

Field notes

Inline validation under an input. Three states, all in mono at the small step.

Neutral — what the field expects.

Accepted — what was understood.

Rejected — what is wrong with it.

10:00–11:00 — .kbd-time, for any New York clock time in running text.

Pager

Above and below any long list, on the journal, the calendar and the prop accounts page. Above because that is where somebody arrives; below because that is where they finish reading and it is the one moment they know they want the next page.

Deliberately not infinite scroll. A page number can be returned to, said out loud and left; a scroll position cannot, and “somewhere near the middle” is not a way to find a trade. It renders nothing at all when no page size on offer could split the list — a pager that cannot shorten anything is furniture.

Card steps

Same component, smaller steps. Rows and cards are not the same problem: twenty-five journal rows is a screen and a half, twenty-five prop cards — each with a progress bar, an attempts list and a form — is a minute of wheel. Seventeen accounts fit inside the smallest ordinary step, so the pager could say 1–17 of 17 and change nothing. A caller whose rows are tall passes CARD_SIZES instead, and the hide rule reads the steps it was given rather than a fixed number.

Review card

A trade a member ticked ask the mentor to look at this one on, shown on the Review tab of admin.html. A card rather than a table row, because the point is to look at one trade properly and a row twenty columns wide is how you end up looking at none of them.

Read-only by construction. The only policy that lets an admin see another person’s trade is select-only and requires the row’s own shared_with_mentor flag, so nothing here can write. The levels stand in for the chart: without price data they are the closest thing to redrawing it, and they answer most of what a critique asks — whether the stop sat inside the noise, whether the target was ever realistic, and whether a planned move was taken in full.

Chart on TradingView

Chart links, not uploads

A member looking at a trade is already looking at a chart. Alt+S in TradingView turns that into a link, and the image behind it sits at a URL derived from the id, so one paste gets both the durable link and something renderable — no upload, no bucket, no signed URL, and nothing of theirs stored anywhere it could leak.

chartLink() in app.js accepts any http(s) URL, not only TradingView: somebody hosting a chart elsewhere should not be told their screenshot is the wrong brand. It returns an inline image only when the URL is one that can be recognised — guessing at a page and rendering it as an img produces a broken-image icon, which reads as a bug rather than as a link. Hotlinked images are wired to fail down to their link rather than to a broken icon.

Ask, as a row action

Asking for a review is a property of a trade, not a form field. Reaching it through edit means opening a form over a trade nobody typed, scrolling past twenty inputs to a checkbox, and saving — to set one boolean. On an imported journal of several hundred rows, nobody does that twice.

The on state drops its underline and takes the bull colour, so asked reads as a fact about the trade rather than as another thing to click. It writes straight through and redraws before the round trip finishes: a toggle that waits on the network reads as broken and gets clicked again, and the second click asks for the opposite of what the first one did.

Findings

Sentences the journal wrote about itself, on stats.html. Conclusions rather than data, so they sit on their own cards with a coloured edge instead of reading as another row in another table.

Each one carries the number it came from, so it can be checked rather than believed. None of them recommends a trade — a finding may say what a habit cost, and may not say what to do next. That line is the difference between a journal and a signal service.

13:00 is costing you. 35 trades in that hour, −$7,830 between them. Leave the hour alone and the period reads +$6,405 instead of −$1,425.

You hold losers 3.6 times as long as winners. Median winner 7 min, median loser 26 min. That is the disposition effect: closing a winner proves you were right, and closing a loser admits you were not.

Bulk selection bar

Shown only while something is ticked, in the journal. A destructive control that sits on screen permanently is one that eventually gets clicked. The confirmation it leads to names the count, the date range and the combined figure — “are you sure?” is a question nobody can answer.

Stated risk rows

One account, one number, on stats.html. R is normally entry minus stop and a broker export carries no stop, so this is the member telling the tool what they risk. The label carries the account and its trade count, so the figure is being set against something recognisable.

Calendar grid

A month of trading days in calendar.html. The swatch carries the sign and is deliberately identical in both themes — the colour is the signal, and a month that reads one way in dark and another in light is two different months. Only the ink changes, and it is dark in both because both swatches are light: white on --cal-up measures 1.5:1, which is unreadable.

The number is always present. Colour alone is no use to anyone who cannot separate red from green, so the swatch is a second encoding of something already written down — never the only one.

This block exists because its absence let a real bug through. The redesign remapped --accent from green to the brand red, and every winning day printed its profit in the losing colour for as long as nobody logged in to look. A component that is not on this page is a component with no regression check.

Accessibility and motion

  • Focus rings appear on keyboard navigation only — :focus-visible, a two-pixel accent outline with offset. Tab through this page to see them.
  • Reduced motion is respected: with the OS setting on, transitions and smooth scrolling collapse to instant.
  • Tap targets in the account strip and toolbars stay above 32px.
  • Contrast: body text on page background is comfortably past WCAG AA. The muted grey is used for secondary text only, never for anything load-bearing.
Known compromise

The site commits to a dark palette rather than supporting both schemes. That is a deliberate choice for a chart-adjacent subject, but it does mean anyone who prefers a light interface has no option here. Print styles invert to black on white so a lesson can be read on paper.

Adding something new

  1. Look for an existing component first. Most new needs are a card, a callout or a table wearing a different hat.
  2. Use tokens, never raw values. A hex code in a component is a future inconsistency.
  3. Land on the spacing scale. If a gap needs to be 18px, use 14 or 22 and see whether it actually mattered.
  4. Add it here. A component that is not on this page will drift, because nothing is checking it.
